# Referências do shadcn/ui (enviadas pelo dono)

Componentes que o dono gostou, guardados como referência para o redesign da gestão (ver `DESIGN.md`).
São `.txt` de propósito: não entram no build. A migração para Tailwind + shadcn foi adiada pelo dono em 2026-10-11;
enquanto isso, cada item é traduzido para o nosso CSS e para os tokens do Jogaê.

| Item | Arquivo | Onde entra na gestão | Dados do Jogaê | Dependências do original |
|---|---|---|---|---|
| Gráfico de área interativo | `chart-area-interactive.tsx.txt` | Financeiro (e um resumo na tela Hoje) | `dailyRevenue` de `GET /reservations/reports` | recharts, card, chart, select (Radix) |
| Barras verticais (uma série) | `bar-charts.tsx.txt` (1) | Financeiro: faturamento por mês ou reservas por dia da semana | relatórios por período (uma chamada por mês) | recharts, lucide-react, card, chart |
| Barras horizontais (ranking) | `bar-charts.tsx.txt` (2) | Financeiro e Quadras: quadras por faturamento, equipamento e cupom mais usados | `courts[]` do relatório; `topCoupons` e `topEquipment` | recharts, card, chart |
| Barras agrupadas (duas séries) | `bar-charts.tsx.txt` (3) | Financeiro: este período contra o anterior, por quadra | duas chamadas do relatório (período atual e anterior) | recharts, card, chart |
| Avatar (imagem, iniciais, bolinha de status e pilha "+3") | `avatar.tsx.txt` | Barra lateral (usuário), Clientes, Equipe e instrutores, reservas (instrutor) | sem foto de pessoa hoje: usar as **iniciais** (a imagem fica opcional) | componente avatar (Base UI/Radix) |
| Bolhas de chat (Bubble, grupo e reações) | `bubble.tsx.txt` | Chatbot da lojinha (`ChatWidget`) e, no futuro, chat de suporte entre gestor e Jogaê (área do dono do Jogaê) | mensagens do chat já existem no chatbot; o suporte exigiria backend novo (conversas e mensagens) | componente bubble, Tailwind |
| Paleta de comandos (Command: busca, grupos, atalhos) | `command.tsx.txt` | Global na gestão (Ctrl+K): ir para qualquer tela ou ajuste, ações rápidas (nova reserva, bloquear horário, criar cupom) e buscar cliente ou quadra | páginas e ações são fixas; clientes e quadras vêm das listas que a API já devolve | `cmdk` (sem estilo, funciona em CSS puro) e lucide-react |
| Formulário (Field: bloco com título e frase, rótulo, ajuda, grade de campos curtos, caixa de seleção em linha, botões) | `field.tsx.txt` | TODOS os formulários da gestão, em especial Configurar: arena, lojinha, nova quadra, cupom, equipamento, funcionário | campos já existentes; o padrão `.field` e `.input` do `primitives.css` é a base | button, checkbox, field, input, select, textarea (shadcn); o Select usa Base UI/Radix |
| Mensagem de chat (Message: avatar + bolha + rodapé "Entregue" + "fulano está digitando") | `message.tsx.txt` | Chatbot da lojinha (`ChatWidget`) e futuro chat de suporte | o `ChatWidget` já tem `messages` (user/assistant) | avatar, bubble, marker, message |
| Chat completo (MessageScroller: rola sozinho só se está no fim, botão "ir para a mais nova", estado vazio, caixa de mensagem com botão de enviar) | `message-scroller.tsx.txt` | Chatbot da lojinha: hoje não rola sozinho, não usa `role="log"` e o "Digitando..." é uma bolha de texto | `sendChatMessage` já devolve a resposta inteira (sem streaming) | cartão, menu, empty, input-group, tooltip, `@ai-sdk/react` só no exemplo |
| Paginação (Anterior, números, reticências, Próxima) | `pagination.tsx.txt` | Rodapé de listas longas: Clientes, reservas e avaliações ("mostrando 1 a 20 de 143") | hoje a API de clientes devolve a lista inteira, sem página; no começo dá para paginar no navegador e depois no servidor | componente pagination (só HTML e CSS, sem biblioteca) |
| Área com rolagem (Scroll Area) e linha separadora (Separator) | `scroll-area.tsx.txt` | Barra de rolagem fina e discreta em todo o painel escuro (listas dentro de cartões, histórico do cliente, paleta de comandos, chat) e linhas finas entre itens de lista | nada de dado; é só visual | Radix no original; **dá para fazer só com CSS** (`scrollbar-width`, `scrollbar-color`), mantendo a rolagem nativa |
| Barra lateral (Sidebar: grupos com título, botão ativo, selo com contador, submenu, recolher para ícones, gaveta no celular, Ctrl+B, variante `inset`) | `sidebar.md` | A CASCA de toda a gestão nova (5 áreas em 2 grupos) | nome da arena e do usuário já existem; contadores (reservas de hoje, avaliações sem resposta) vêm das listas da API | Radix (Sheet, Tooltip, Collapsible, DropdownMenu); dá para fazer com CSS, React e `<dialog>` |
| Spinner dentro de um Item (linha com ícone, título e valor à direita) | `spinner-item.tsx.txt` | Estados "salvando…", "confirmando reserva…" e, no futuro, "aguardando Pix"; o Item é o molde das linhas de Configurar (ícone, título, ação à direita) | nada de dado | spinner e item (shadcn); o spinner é só CSS |
| Interruptor (Switch + Label) | `switch.tsx.txt` | Configurar ("receber reservas online"), cupons e equipamentos (ativo/inativo em vez do botão "Desativar"), equipe | os campos `active` que já existem | switch (Radix); dá para fazer com `<input type=checkbox role=switch>` e CSS |
| Tabela (legenda, cabeçalho, valores à direita, rodapé com total) | `table.tsx.txt` | Financeiro (por quadra, com total do período), Clientes, reservas | já tem a base `.data-table` em `panel-kit.css`; falta o rodapé de total e a legenda | só HTML semântico + CSS |

Padrão comum a todos os gráficos: título e descrição no cabeçalho, linha de tendência no rodapé ("Trending up by 5.2% this month" + ícone) com uma frase de contexto abaixo, grade só horizontal, eixos sem linha, dica ao passar o mouse e `accessibilityLayer` (o gráfico é navegável pelo teclado).
